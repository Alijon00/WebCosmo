# ИИ-ассистент «MISSION CONTROL AI»

Ассистент по МКС, космосу и астрономии для сайта проекта. Ядро написано
самостоятельно, **без поисковых библиотек** (никаких lunr / fuse / minisearch):
собственная нормализация текста, собственный индекс BM25 и собственная
маршрутизация намерений.

Архитектура двухконтурная:

- **Основной контур — офлайн-движок.** Работает полностью в браузере, без сети.
- **Резервный контур — внешняя модель (Gemini).** Подключается только тогда,
  когда в базе знаний нет ответа, и **никогда** не является обязательным: сайт
  работает без интернета и без API-ключа.

---

## 1. Схема маршрутизации

Каждый вопрос проходит конвейер из пяти шагов. Первый сработавший шаг и даёт
ответ (`src/lib/assistant/answer.ts`):

```
                 ┌─────────────────────────────────────────────┐
   вопрос ─────► │ normalize()  — нижний регистр, стеммер,       │
                 │                синонимы, токенизация          │
                 └─────────────────────────────────────────────┘
                                    │
             ┌──────────────────────┼───────────────────────────┐
             ▼                                                    
   1. INTENT (живые данные трекера)                              
      LOCATION / DISTANCE / ALTITUDE / VELOCITY / ORBIT_TIME  ──► source: live
             │  (нет живого намерения)
             ▼
   2. OFF_TOPIC  (запрос не пересёкся со словарём космоса)  ─────► source: fallback
             │  (вопрос по теме)                                   (вежливый отказ + 3 примера)
             ▼
   3. BM25    bestScore ≥ THRESHOLD ?  ──да──────────────────────► source: local
             │  (нет — ответа в базе нет)
             ▼
   4. EXTERNAL  POST /api/ask (Gemini) вернул текст ? ──да───────► source: external
             │  (нет / ошибка / таймаут / нет ключа / офлайн)
             ▼
   5. FALLBACK  «не нашёл точного ответа» + ближайшие темы ──────► source: fallback
```

Каждому источнику соответствует **плашка** под ответом в UI:

| source     | точка          | подпись                                   |
|------------|----------------|-------------------------------------------|
| `live`     | 🟡 жёлтая       | Телеметрия в реальном времени             |
| `local`    | 🟢 зелёная      | База знаний проекта · *‹заголовок статьи›* |
| `external` | ⚪ серая        | Внешняя модель · не проверено             |
| `fallback` | —              | Не найдено в базе                         |

## 2. Нормализация текста (`normalize.ts`)

Прежде чем что-то искать, запрос и тексты базы приводятся к единому виду:

1. **Нижний регистр + снятие пунктуации.** Регулярное выражение `\p{L}\p{N}`
   (Unicode-режим) сохраняет латиницу, кириллицу **и** таджикские буквы
   `ғ ӣ қ ӯ ҳ ҷ` — они тоже «буквы», поэтому отдельный список не нужен.
2. **Лёгкий стеммер.** Отсекает один словоизменительный суффикс, если основа
   остаётся не короче 3 символов. Суффиксы отсортированы от длинных к коротким:
   - **ru:** `-ами -ого -ыми -ует -ать -ов -ая -ые -ий -ой -ах -ем -ии …`
   - **tg:** `-ҳо -ро -ем -ед -анд -и -ест …`
   - **en:** `-ing -ed -es -s …`

   Благодаря этому «орбита», «орбиты», «орбитой» → одна основа `орбит`.
3. **Словарь синонимов** (`synonyms.json`, легко пополняется). Каждая группа
   имеет канонический токен; все формы сводятся к нему, поэтому
   `мкс = iss = станция = истгоҳ = space station`, `орбита = мадор = orbit`,
   `скорость = суръат = velocity`, `высота = баландӣ = altitude` и т.д.
   Многословные синонимы («space station») заменяются отдельным фразовым
   проходом до токенизации.

## 3. Поиск BM25 (`bm25.ts`) — разбор формулы

BM25 (Okapi BM25) — ранжирующая функция, улучшенная версия TF-IDF. Она отвечает
на вопрос «насколько документ *D* релевантен запросу *Q*?» и складывает вклад
каждого слова запроса:

```
score(D, Q) = Σ_term  IDF(term) · ( tf · (k1 + 1) )
                                   ─────────────────────────────────────
                                   tf + k1 · (1 − b + b · |D| / avgDL)
```

### IDF — обратная документная частота

```
IDF(term) = log( 1 + (N − df + 0.5) / (df + 0.5) )
```

- **N** — число документов в корпусе.
- **df** — в скольких документах встречается слово.
- Редкое слово (маленький `df`) несёт больше информации → больший вес.
- `+0.5` — сглаживание (нет деления на ноль). Внешнее `1 +` гарантирует
  `IDF ≥ 0` даже для слова, которое есть почти во всех документах.

### Насыщение частотой — параметр `k1 = 1.5`

Числитель `tf·(k1+1)` растёт с частотой слова, но знаменатель ограничивает этот
рост — 10-е вхождение слова добавляет почти столько же, сколько 9-е. `k1`
управляет скоростью насыщения. Значение **1.5** — сбалансированное из
литературы (TREC): статьи короткие, и мы не хотим, чтобы одно слово, повторённое
несколько раз, задавило все остальные.

### Нормализация по длине — параметр `b = 0.75`

Множитель `(1 − b + b · |D|/avgDL)`, где `|D|` — длина документа, `avgDL` —
средняя длина по корпусу. При `b = 1` длина учитывается полностью (длинные
документы штрафуются, ведь у них больше шансов случайно содержать слово), при
`b = 0` — не учитывается. Стандартное **0.75** — умеренный штраф: наши статьи
разной длины (3–6 предложений), и это не даёт длинным текстам несправедливого
преимущества.

### Бусты полей

Совпадение в **заголовке** усиливается ×2, в **тегах** ×1.5 (добавляются к
эффективной `tf`). Так статья, у которой слово запроса стоит в заголовке,
поднимается выше статьи, где оно лишь мелькнуло в теле.

### Индексация и `reindex()`

`tf`, `df`, длины и `avgDocLen` считаются **один раз** при построении индекса и
мемоизируются; на запрос остаётся только сложить вклад термов. Метод
`reindex()` пересобирает индекс — это используется, когда во время демонстрации
через админ-панель добавляют новую статью (индекс обновляется на лету, без
перезагрузки).

## 4. Маршрутизация намерений (`intents.ts`)

Некоторые вопросы нельзя честно ответить статьёй — на них отвечают **живые
данные** трекера МКС (`useISS`, источник `wheretheiss.at`). Такие вопросы
перехватываются до BM25, и в шаблон на нужном языке подставляются свежие цифры:

- **LOCATION** — «где сейчас МКС» → широта/долгота + примерный регион.
- **DISTANCE** — «далеко ли от Душанбе» → расстояние (гаверсинус) + высота.
- **ALTITUDE / VELOCITY** — текущая высота / скорость.
- **ORBIT_TIME** — виток ≈ 92 мин, ≈ 16 витков и ≈ 16 рассветов в сутки.
- **CREW** — живого источника состава экипажа нет → вопрос честно передаётся
  базе знаний (там есть статья про экипаж).
- **OFF_TOPIC** — запрос не пересёкся ни со словарём космоса, ни со словарём
  базы → вежливый отказ и три примера уместных вопросов.

Если трекер офлайн, живые намерения отвечают честно: «сейчас нет сигнала» либо
показывают последнюю известную позицию с пометкой, что данные могли устареть.

## 5. Порог THRESHOLD — как подобран эмпирически

Порог решает, доверять ли локальному ответу. Он подобран скриптом
`scripts/tune-threshold.ts` (запуск: `npm run tune`), который прогоняет 24
вопроса «в базе» и 10 посторонних и печатает `bestScore` для каждого.

**Реальные цифры прогона (язык ru):**

```
«В базе»       n=24   min=3.38   median=11.93   avg=11.99   max=20.65
«Посторонние»  n=10   median=2.20   max=9.87
```

Распределение почти разделяется на два кластера. Посторонние вопросы в основном
дают 0–2.2, но есть несколько выбросов из-за случайных совпадений слов, которые
реально встречаются в статьях:

- «какой курс **доллара** сегодня» → 4.49 (слово «долларов» есть в статье о
  стоимости МКС);
- «какая погода в **Душанбе**» → 4.49 (Душанбе упомянут в статье об обсерватории);
- «сколько **стоит** билет…» → 9.87 (заголовок «**Сколько стоит** МКС»).

**Выбранное значение: `THRESHOLD = 5.0`** (`src/lib/assistant/config.ts`).

Обоснование: порог 5.0 отсекает выбросы-посторонние на 4.49 и сохраняет **23 из
24** релевантных вопросов (полнота ≈ 96 %). Единственный отсекаемый релевантный
вопрос — про стыковку (3.38): его формулировка слабо совпадает со словами базы,
и он честно уходит во внешний контур / fallback, а не выдаёт наугад чужую статью.
Мы сознательно смещаем порог в сторону **точности**, а не полноты: лучше честно
сказать «не нашёл», чем показать неверную статью. Оставшийся выброс на 9.87
возвращает статью о стоимости МКС — это тематически близкий ответ, и вреда он не
наносит.

## 6. Почему локальный retrieval первичен, а генеративная модель — резерв

1. **Достоверность.** Локальные ответы — это тексты, которые мы написали и
   проверили сами. Генеративная модель может «галлюцинировать» — выдумывать
   факты и цифры. Поэтому первое слово всегда за проверенной базой.
2. **Работа офлайн.** Олимпиадная защита не должна зависеть от интернета и от
   доступности внешнего API. Движок BM25 работает целиком в браузере.
3. **Скорость и стоимость.** Локальный ответ мгновенный и бесплатный; обращение
   к внешней модели — это задержка и расход квоты.
4. **Прозрачность.** Под каждым ответом видно, откуда он: телеметрия, база,
   внешняя модель (помечена «не проверено») или честный fallback.

Внешняя модель нужна лишь чтобы вежливо ответить на редкий вопрос, которого нет
в базе, — но и её ответ помечается как непроверенный.

## 7. Резервный контур Gemini (`server/ask.ts`, `/api/ask`)

- Ключ хранится в `.env` как `GEMINI_API_KEY` и читается **только на сервере**;
  в браузерный бандл он не попадает никогда (проверяется: `grep GEMINI dist/`
  пусто). Клиент шлёт на `/api/ask` лишь `{ query, lang }`.
- Модель `gemini-2.0-flash`, таймаут **8 секунд** через `AbortController`.
- **Rate limit** — 10 запросов в минуту с одного IP (in-memory счётчик).
- **Системный промпт** жёстко ограничивает модель: отвечать только про космос,
  МКС и астрономию; на остальное — вежливый отказ; 2–4 предложения; простой
  язык; отвечать на языке из параметра `lang` (tg/ru/en); не выдумывать точные
  цифры.
- Эндпоинт поднимается Vite-плагином в `vite dev` и `vite preview`. Для реального
  продакшена этот же обработчик переносится в serverless-функцию без изменений.
  На статичном GitHub Pages эндпоинта нет — клиент это молча воспринимает как
  сигнал уйти в локальный fallback.

**Проверено вручную** на dev-сервере:

| запрос                         | ответ    |
|--------------------------------|----------|
| POST без ключа                 | `502` → клиент уходит в fallback |
| GET (не POST)                  | `405`    |
| пустое тело                    | `400`    |
| 11-й запрос за минуту          | `429` (rate limit) |

### Гарантия работы офлайн / без ключа

Клиентская функция `askExternal` при **любой** ошибке (нет сети, таймаут, нет
ключа, rate limit, 404 на статике, битый JSON) возвращает `null` и **никогда не
бросает исключение**. Оркестратор `answer.ts` дополнительно оборачивает вызов в
`try/catch`. Итог: что бы ни случилось с внешним контуром, UI не ломается, и
ответ приходит из локальной базы. Это покрыто тестами (`answer.test.ts`:
внешний вызов = `null` и внешний вызов = `throw` → оба дают `source: 'fallback'`).

## 8. Как добавить запись в базу знаний

Формат статьи (`src/data/knowledge/{tg,ru,en}.json`):

```json
{
  "id": "уникальный-идентификатор",
  "title": "Заголовок статьи",
  "tags": ["ключевое", "слово", "тег"],
  "body": "3–6 предложений простым языком, без выдуманных точных цифр."
}
```

Правила:

- `id` одинаковый во всех трёх языках — это одна и та же статья.
- `tags` пишутся на языке файла (по ним усиливается поиск).
- Тексты — простым языком для школьника, без выдуманных фактов.

**Два способа добавить статью:**

1. **Навсегда** — дописать объект в соответствующий JSON-файл и пересобрать.
2. **На лету, во время демонстрации** — открыть админ-панель
   `/admin/knowledge` (или скрытую кнопку ⚙ в виджете), заполнить форму. Статья
   сохранится в `localStorage`, индекс BM25 пересоберётся сразу (`reindex`), и
   ассистент тут же начнёт на неё отвечать — без перезагрузки. Там же есть
   мини-поле «проверить ответ», удаление статей и экспорт добавленного в JSON
   (чтобы перенести в основную базу). Покрыто тестом `admin.test.ts`:
   добавленная статья находится поиском немедленно.

## 9. Как система защищена от галлюцинаций

1. **Первичность проверенной базы.** При достаточной релевантности отвечает
   локальная статья, а не генеративная модель.
2. **Порог со смещением в точность.** Ниже `THRESHOLD` локальный ответ не
   выдаётся — лучше «не нашёл», чем наугад.
3. **OFF_TOPIC-фильтр.** Вопросы вне тематики отсекаются вежливым отказом и не
   доходят даже до внешней модели.
4. **Fallback ничего не выдумывает.** Он лишь сообщает «не нашёл точного ответа
   в базе» и предлагает 3 ближайшие темы кликабельными кнопками.
5. **Ограниченный системный промпт** у внешней модели: только космос, короткий
   ответ, без выдуманных цифр.
6. **Честная маркировка.** Ответ внешней модели всегда помечен плашкой
   «Внешняя модель · не проверено», живые цифры — «Телеметрия в реальном
   времени», база — с указанием статьи-источника.

```
  bm25.ts         — индекс BM25 с нуля
  intents.ts      — маршрутизация намерений на живые данные
  knowledge.ts    — загрузка базы + слияние с localStorage + мемоизация индексов
  external.ts     — клиент /api/ask (тихий откат)
  config.ts       — THRESHOLD и прочие константы
  answer.ts       — оркестратор конвейера
  __tests__/      — normalize / bm25 / intents / answer / admin
src/data/knowledge/{tg,ru,en}.json  — база знаний (по 46 статей на язык)
src/components/assistant/           — виджет чата + админ-панель
server/ask.ts                       — серверный обработчик Gemini
scripts/tune-threshold.ts           — подбор порога
```

Запуск: `npm test` (33 теста), `npm run tune` (подбор порога), `npm run build`.

**Что покрыто тестами:** BM25 ранжирует релевантное выше нерелевантного;
стеммер сводит формы слова к одной основе; синонимы «истгоҳ» и «мкс» дают
одинаковый результат; «где сейчас мкс» → LOCATION, «как приготовить плов» →
OFF_TOPIC; score выше порога → `local` без сетевого вызова; score ниже порога →
вызов `/api/ask` (мок); падение внешнего вызова → `fallback` без поломки UI;
отсутствие ключа → `generateAnswer` возвращает `null`; добавленная в админке
статья находится поиском сразу.
